# 初めに
いや〜朝夜にかけて少し肌寒い季節になってきましたね〜
個人的には過ごしたい季節になってくれてよかったです。
さて今回はAI普及後のエンジニアがどのように成長したらいいのか？どんなキャリアがいいのか？思っていることを記載しようと思います。
:::message

Cursor、Claude Code、Codex、Devinこの辺が登場してから特にエンジニアのコードに対する向き合い方、キャリアが変わった気がします

今更ですがコード、レビュー、テストをエンジニアではなく


オメガマスターです。未経験から受託開発に入り、AI Editor を日常使いしながら開発している身から、**これからのエンジニアキャリアの軸**を整

# いま起きている変化

## 実装のスピードと、レビューの量

生成AIやAI Editorの普及で、**最初の実装までの時間**は短くなりました。
その代わり、チームではこんな変化を感じることが多いはずです。

- レビューする行数・ファイル数が増える
- 「動くけど、責務がズレている」コードが混ざる
- 仕様の穴を埋める前に実装が進み、後から直すコストが増える

未経験の頃に書いた記事でも触れましたが、フロントで `map` すれば表示できるのに、本来はSQLやAPIの責務で直すべきケースは、AIが増幅しやすいタイプです。
**出力量が増えた＝品質判断の仕事が増えた**、と捉えるとキャリアの見え方が少し変わります。

## ペアプロの相手が増えた

ペアプロの相手は、もはや人だけではありません。Agent と一緒に書く日が当たり前になってきています。
面接や業務でも「AIで何をしたか」「どう効率化したか」が聞かれる場面は増えています（これは良い変化でもあります）。

ただし **「AIに聞いた」ことと「自分が理解している」ことは別** です。
理解が追いついていないままマージされるリスクは、個人の問題ではなくチームの問題になります。

# 相対的に薄くなりつつある価値

以下は「不要になる」という意味ではなく、**それだけでは差にならない**、というニュアンスです。

- 初見のボイラープレートだけを書くこと
- ツール名やプロンプトの型だけ知っていること
- エラーメッセージをそのままAIに投げ、返ってきたコードを貼るだけのこと

AIは平均的な答えを速く返します。だから **平均と同じことをするだけ** では、キャリアの武器になりにくいです。

# 厚くなっている価値（キャリアの芯）

## 1. 問いを立て、方向を合わせる

「こう動かしたい」以前に、**何を直すべきか** を決める力です。
上司やチームに「この理解で合っていますか？」と聞くのは、弱さではなくプロの仕事です。
AIに聞く前に人に聞く、AIの案を持って人に確認する——この順番が大事だと感じています。

## 2. 責務と境界を守る

フロントとバック、SQLとアプリケーション、認証と表示。
**どこで直すのが正しいか** は、AIが文脈を誤ると一発でズレます。
境界を理解している人は、レビューでも障害対応でも頼られます。

## 3. 編集と説明責任

生成されたコードを **採用するか、直すか、捨てるか** は人間の判断です。
また、なぜこの実装なのかを、非エンジニアや後任に伝える説明も残ります。
「動いたからOK」で終わらせない人に、信頼が集まります。

## 4. 人間関係と教育

[あなたの言葉が新人を遠ざけていませんか？](/kanbaramasatoshi/your-words-causing-discomfort-to-the-newcomer) でも書きましたが、
「コード読んで」「調べて」だけが返ると、新人は拒絶されたように感じます。
AI時代は **「AIに聞いて」だけ** でも同じ構図になり得ます。
先輩は、Agentの代役ではなく **頼れるラストマン** であることが、これからも価値になります。

# キャリアの「型」は3つくらいで十分

正解は一つではありません。今の会社・案件で伸ばす軸を選ぶイメージです。

| 型 | 伸ばすもの | 向いている人の例 |
| --- | --- | --- |
| 深掘り型 | ドメイン×技術の専門性、設計の最後の砦 | 一つの領域を極めたい |
| 橋渡し型 | 要件の曖昧さを減らす、仕様と実装の翻訳 | コミュニケーションが得意 |
| 編集・運用型 | リリース、観測、コスト、セキュリティ、AIワークフロー | 全体を回すのが好き |

受託でフロントもバックも触る環境は、最初は **橋渡し＋深掘りの入り口** になりやすいと思います。
[30代実務未経験が受託開発会社に入社して半年ちょっと立った頃](/kanbaramasatoshi/no-experience-30-sixmonths-work-experience) のように、幅を広げる選択もキャリアの一部です。

# これから1年でやってみたいこと

煽りではなく、自分にも言い聞かせるリストです。

1. **小さな機能を仕様→実装→レビュー→振り返りまで一人で回す**（ミニアプリでも可）
2. **AIに聞く前に「ここまで理解した」ことを一行で書く**（メモでもPRでも）
3. **一テーマだけ下まで掘る**（例: SQL、認証、デプロイのどれか一つ）
4. **レビューで指摘された点をチェックリストにする**（次のPRで自分で潰す）
5. **先輩は拒絶にならない返し方を意識する**（忙しくても「どこまで分かった？」から入る）

# 最後に

エンジニアキャリアは「コードを書く量」だけでは測れなくなってきています。
それでも **問題を切り分け、品質に責任を持ち、人とAIの出力を編集する** 仕事は残り、むしろ重要になっている——今はそう捉えています。

変化の速さで不安になるのは自然です。だからこそ、一年単位で小さく試して、軸を更新していくのが現実的だと思います。
