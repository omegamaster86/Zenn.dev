---
title: "よくある誤解"
---

| 誤解 | 実際 |
| --- | --- |
| Next.js の入口（ページや proxy／middleware）を守れば安心 | Supabase の API（`*.supabase.co`）はブラウザから publishable key で直接呼べる。Next.js を経由しないアクセスは Next.js 側では止められない |
| ページで認証チェックしていれば Server Action も守られる | Server Action は直接 POST で呼べる。ページ単位のチェックはアクションには及ばないので、アクションごとに認証・認可が必要 |
| `service_role`（secret key）をサーバーで使えば安全 | secret key は RLS を迂回する。サーバーで使うほど、アプリ側の認可漏れがそのまま漏えいにつながる |
| ユーザーの JWT でサーバーから Supabase を呼べば「サーバーに集約」できている | ブラウザも同じ JWT を持っているので、同じ呼び出しを直接実行できる。DB 側の権限を絞らない限り集約にはならない |
| Supabase が攻撃を自動で検知・遮断してくれる | 認証まわりのレート制限や CAPTCHA はあるが、全 API への攻撃をリアルタイムに自動判定・自動遮断してくれるわけではない。監視と対応は自分たちで用意する |
| 暗号化しておけば漏れても大丈夫 | 正規の経路で復号できる権限があれば読めてしまう。暗号化はアクセス制御の代わりにならない |
